# 08：表格排序、小时分组与批量显示性能

Blocked by: 07
状态：实现与桌面回归完成；实际窗口缩放体验待用户验收，未提交。

## 要求与实现

- 本地默认修改时间降序，手动默认名称升序，后续添加保留当前排序。
- 本地且按时间排序时，以本地日期＋小时分组交替浅色背景；其他排序和手动表不着色，高对比度模式不使用淡色。分组在排序或行集合变化时计算，绘制只查缓存，不创建逐行样式。
- 原逐行 Rows.Add 改为预建行后一次 AddRange，批量完成后统一同步勾选状态、排序与分组。
- 启用表格双缓冲；表头复选框只在位置变化时更新，不重复 BringToFront。

## 诊断与验证

- 修复前 1,000 条添加触发 1,000 次 RowsAdded，约 63ms；30 次缩放并 DrawToBitmap 约 551ms，格式化 2640 次。性能回归断言先红后绿。
- 批量修复后 1,000 条约 17ms，1 次事件。最终 10,000 条手动约 283ms、本地约 363ms，均 1 次事件。
- 最终 30 次缩放绘制：空表 242ms；1,000 条 622ms；10,000 条手动 537ms、本地 507ms。格式化次数分别 0／2640／2640／2400，布局均 30 次；未随总行数全量绘制。
- 桌面 53 项全部通过；覆盖排序、同小时与跨日分组、升降序、切换排序、清空重载、批量发布和可见行绘制上界。耗时仅为本机离屏测量，不作严格性能门槛。
- 双缓冲用于减少分块闪烁，离屏耗时未证明缩放显著加速，不能据此宣称用户的拖动卡顿已完全解决。需用户实际拖动空表、大表窗口确认；若仍卡顿继续调查实际窗口重绘路径，不重复堆叠缓冲方案。
