## 留白原因与边界

main 与游戏分支都包含相同的 `LocalManifestSummary` 创建与加入布局代码；游戏分支没有新增此行。该空 Label 作为可见控件始终加入自动布局，清空文字不等于移除控件，其首选尺寸与边距仍参与布局；因此是已有的空控件占位设计，不是新加的导入结果内容。

游戏分支调整了外框进度布局，可能影响留白的视觉表现，但未对同一 DPI／尺寸下 main 与游戏分支做独立画面对照，不能确定为何用户仅在 worktree 中观察明显。网络 worktree 未检查，不能宣称其留白来源已经核实。此次直接删除冗余控件，不以强制高度、隐藏空格或窗口重绘掩盖问题。

## 高度不足：仅建议，未实现

持续压缩间距只能适配有限的窗口、DPI 和字体组合。自动高度提示、按钮换行先占空间，百分比行只得到剩余高度，内容所需高度超过剩余空间时仍可能被裁切。

建议将页面内部输入区放入可滚动视口，为列表保留合理最小尺寸；顶部流程与底部状态／导航仍留在外框。滚动属于当前页面，不给整个 Form 加滚动条，也不移动扫描按钮的语义分组。之后验证 100%／125%／150%／200% DPI、长提示与窄窗口组合，检查控件相对父容器的裁切和互相覆盖，而不只检查是否位于 Form 边界内。本次不实现该方案，也不宣称遮挡根因已全部解决。

依据：Microsoft Windows Forms `AutoSize Behavior in the TableLayoutPanel Control` 文档，自动高度行先按首选尺寸分配，百分比行使用剩余空间。https://learn.microsoft.com/en-us/dotnet/desktop/winforms/controls/autosize-behavior-in-the-tablelayoutpanel-control
