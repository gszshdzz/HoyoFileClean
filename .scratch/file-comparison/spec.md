# 模块 2：多输入、对称清单比较

## 用户确认的目标与边界

直接向比较模块的 A、B 两侧输入一份或多份清单，不将清单组合作为独立模块，不生成中间文件。两侧平等、共用读取与校验规则；输出 A 独有、B 独有、共有但大小或 MD5 不同的条目，保留两侧身份。两侧之间的差异是正常结果，不报错。

用户另行确认：同一侧多份输入出现同路径、大小或 MD5 相互矛盾的记录，属于输入问题，应报错。相同记录去重，不能任取一份掩盖冲突。

最小实现仅接受现有模块输出的 JSON，复用 .NET JSON/集合及项目已有路径校验、安全写出，不新增依赖、组合命令、版本元数据管理、逐份比较模式或清单格式兼容层。只读输入，不访问扫描根目录、不联网、不移动文件。

## 比较与验收

命令与报告字段以 [README](../../README.md#清单比较) 为准。双方都有 MD5 才比较内容校验值；否则明确记录仅比较大小，不将缺少哈希当作内容差异。扫描排除与跳过链接的范围不误报为独有，且两侧对称处理。

自动验证：三类差异及 A/B 对调、多输入去重、同侧冲突、轻重扫、扫描范围边界、损坏输入、安全路径、拒绝覆盖、无扫描根目录访问和 CLI 退出码；回归现有 76 项测试。只验证本次输入集合差异，不宣称清单覆盖完整或文件可移动。

实施与验证记录见 [任务 01](issues/01-file-comparison.md)。
