# 文件实际处理

用户确认：接通回收站、永久删除、移动；支持跨卷；整批预检，执行失败立即停止。移动保留相对目录，可将已移出的文件整体拖回根目录，不引入恢复系统、自动回滚或新依赖。

## 安全约束
- 只操作本次明确选择且属于当前游戏扫描范围的普通文件，不处理参考侧、未扫描范围或目录。
- 复用路径和范围校验；拒绝链接、重解析点、越界、重复与覆盖，移动目标与源根目录不能互相包含。
- 全批次只读预检后才开始；逐项执行前重新核验大小及已有 MD5。轻扫不能识别扫描后同大小的内容变化，必须明确限制。
- Windows 原生接口，不调用 agent safe-delete；回收站不可用不降级为永久删除。
- 原生句柄保护操作中的目录与文件；跨卷仅在复制成功且内容核验后删除源文件，失败保留可见状态，不扩大清理范围。
- 不删除空源目录，不自动清理失败残留，不自动重试、不自动回滚。
- 用户后续确认采用最小实现：防范常见误操作、游戏／更新器／编辑器占用与普通文件变化，不把同权限恶意程序的瞬时目录重解析点篡改纳入本轮。直接取得文件锁，锁冲突提示关闭相关程序，不扫描进程或引入进程检测模块。
- 执行时锁定导航与重复启动；结束后保留逐项结果，旧扫描与比较不得继续授权下一次执行。

## 验证
隔离目录验证实际移动、删除、回收站；验证未选文件与外部哨兵内容不变、目标冲突整批无操作、链接与非法路径拒绝、文件变化拒绝、失败后停止。跨卷和真实系统回收站的环境限制单独报告。先运行相关类，再阶段全量回归。

## 后续澄清（session 25）

- 用户无法在已清理的真实游戏目录验收，也不希望自行造垃圾样本。由 agent 负责创建隔离样本并完成自动自验，不把逻辑验收交回用户。
- 回收站当前按文件产生独立条目，不把一次清理打包成目录；用户本次询问行为，不构成修改条目形态的授权。
- 撤回失败的目录强化试验不等于原实现已精简。2026-11-21 后续去除手工原生缓冲区分配／释放，并复用每批回收线程及系统对象，四个新增业务文件从 544 行降到 537 行，仅减少 7 行，不称为大幅精简或已经证明最小。

## 本轮补充与提交要求（session 25）

- GUI 所有文件大小统一自动单位及约 3 位有效数字；B 级小文件直接显示实际整数。格式逻辑共用，单位／精度放呈现配置；表格保留数值用于排序，CLI 及导出数据仍用原始字节。
- 操作第四步默认隐藏集合中的文件必须额外警告，包括默认隐藏范围、本地版本元信息差异可能正常、删除／移走可能影响游戏。复用当前识别结果对应的配置集合，不特判某个游戏或 pkg_version。
- 回收站提示逐个回收会出现大量独立条目、列表展平不保留目录结构，Windows 保存每项原位置；可选移动保留相对目录。
- 每次有效操作固定至多两次确认：先将所有风险合并为一次提示，再做最终确认；任意阶段取消均不发起处理。无选择或忙碌时不弹窗；无效输入只报输入错误。
- 使用 code-review 两轴审查整个 worktree，包括未跟踪文件及此前实际文件操作实现；修复确认的问题、完成代理自验后直接提交，不推送。提交编号 25，记录 message 与编号后随提交保存。
- 最终提供精简、可复制的主线合并说明：需求、变更及影响、编号／worktree／commit、验证与必要限制。
