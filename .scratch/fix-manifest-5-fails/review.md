# 四份清单格式误判的最小修复验收

日期：2026-11-21。基线：HEAD，审查当前未提交改动。范围仅为四份有效补丁清单，不处理不完整缓存。

## 改动与审查结论

- `core/ManifestConverter.cs`：JSON 语法解析失败时，重放原始解码字节至现有二进制解析器；二进制编码无效或为空时保留原 JSON 异常，不吞掉元数据、路径、集合等校验错误。
- `tests/PreDownloadManifestTests.cs`：新增三组压缩／未压缩用例，分别覆盖有效 `0A7B0A52` 前缀、同前缀非法 MD5、损坏 JSON 的错误码及不发布输出。
- 新增断言钉住完整文件记录、数量、总大小、补丁类型和拒绝行为，无仅存在性或恒真断言；合成样本不依赖用户缓存。
- 既有 `docs/history/manifest-parse-failures-2026-11-20.md` 是修复前诊断证据，本次不改写。

风险评估：中（输入解析边界）；未发现阻断交付的安全问题，建议验收。没有新增依赖、公共接口或文件写入路径，没有删除安全校验。

## 历史与调用影响

- `git blame` 显示直接按 `{` 选择 JSON 的逻辑源于 `112a29c7`，官方网络禁止本地格式的保护源于 `8f433887`；本次保留后者，不放宽官方网络格式合同。
- 当前直接受影响的是 `ManifestConverter.Read` 的本地内容识别，以及经过它的 `Convert` 和桌面 `ReferenceParser`；`NetworkManifestClient` 使用的官方格式分支仍在重试之前拒绝不支持的输入。
- 重试前排空受限原流，重试流同样使用 `ManifestReadStream` 的大小上限和取消检查；原有外层压缩错误和内容摘要校验仍保留。失败分支增加有限次数重读，不缓存整份解码内容。
- 以 HEAD 对照审查了全部两份代码／测试差异及本次诊断记录，没有涉及移动、删除、网络来源或其他业务变更。未作全仓安全审计。
