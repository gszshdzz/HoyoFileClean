# 06：最多两个 DNS 地址并发连接

状态：实现与自动验证完成，待用户实际验收，未提交。

## 根因与取舍

- 原实现顺序尝试 DNS 地址，每地址最多等 2 秒。本机实测首地址不可达而后续地址数毫秒连通，造成首次查询／获取额外等待。DNS 本身仅数毫秒；底层路由为何不可达尚未确认。
- 不可达地址并不固定：本轮先观察到 `123.172.123.192`，后观察到 `36.104.134.109`。不按地区、运营商或特定地址修补，不维护黑名单。
- 默认 .NET 与 Windows 原生 WinHTTP 对照都出现约 21 秒等待。WinHTTP 对照使用系统 COM 接口，不是 WinHttpHandler 包测试。
- 优先检索成熟可复用实现，但本轮未找到适合直接引入的 .NET 10 库。用户通过选择卡确认接受最小双连接实现；未新增依赖。

## 实现范围

- 仅修改 `core/OfficialConnection.cs` 及连接测试。保留 DNS 第一个地址，第二地址优先选择不同前缀：IPv4 /24、IPv6 /64；仅作分散尝试的启发式，不代表真实网络或运营商归属。
- 最多两个 TCP 尝试立即并发，失败后补充剩余地址，每地址仍最多 2 秒；不并发发送 HTTP 请求或下载清单。
- 采用先成功的连接，取消并等待其他尝试退出，释放未采用的成功连接。TLS 验证、代理、连接池和官方来源限制仍沿用原逻辑。
- 本轮 DNS 前两个地址已属不同前缀，无法证明前缀优先本身比直接取前两个更快；已验证的是有限并发能消除串行等待。

## 验证结果

- 回归测试先在旧实现出现 5 项失败，再在新实现 10 项全部通过；覆盖提前胜出、IPv4／IPv6 前缀选择、并发上限、剩余地址尝试、取消与未采用连接释放。
- 核心常规：Total 236，Errors 0，Failed 0，Not Run 4，即 232 项通过；显式冷／热联网对照另行执行 2 项通过。
- 桌面常规：Total 96，Errors 0，Failed 0，Not Run 1，即 95 项通过；未运行项为既有显式诊断。
- 现有 `NetworkTimingTests` 正式实现实测：官服冷目录 443 ms、五份下载 713 ms，合计约 1.16 秒；热目录 196 ms、下载 307 ms。两次 TCP 尝试同毫秒启动，可用地址约 4 ms 成功，另一连接立即取消。
- 按 GUI 顺序查询两服的正式实现实测：首次官服 153 ms、国际服 1104 ms，总计 1261 ms；再次总计 243 ms。
- 以上为新客户端连接池的冷／热测量，不是清空系统 DNS 或 TLS 缓存后的结果；网络测量并非严格同时对照。官服五份清单约 13.7 MB，国际服下载本轮波动明显，不承诺总耗时始终低于一秒，不扩大到下载优化。
- `git diff --check` 无空白错误；Git 提示修改文件将在下次触及时由 LF 转为 CRLF。

## 用户验收

重新启动桌面程序，在网络来源页分别观察首次“查询”和所选区服首次“获取”，再重复一次。确认没有此前固定数秒的连接停顿，清单数量与解析正常；国际服网络波动应与固定地址等待区分。
