# 07：桌面仅查询所选区服并分离查询／获取

状态：实现完成，网络专项及核心回归通过；桌面完整回归存在布局失败，未完成整体验证，待用户验收。未提交。

后续更正：用户澄清查询应发现区服与当前版本，而不是查询 manifest 目录。本任务的按钮职责已被 [08](08-discovery-and-network-cancellation.md) 取代，下文保留为当时的调查与验证记录。

## 用户要求与根因

- 用户反馈国际服约 5 秒，要求先实测；每一步只请求所需信息，不请求未选区服。
- 原桌面查询按顺序访问官服、国际服，仅用于过滤程序内已有区服候选；获取又重新查询分支和构建目录。问题是步骤职责混杂，而非接口强制需要跨服请求。
- 候选仍为现有官服／国际服，不表示当前可用。固定业务数据外置另记于 `.scratch/configuration/issues/01-external-business-data.md`，本轮不实施。

## 本轮改动

- 区服候选直接显示，默认官服；选择时不联网。
- 查询只调用所选区服的分支与构建接口，成功后保留内存目录、显示实际版本并启用获取。
- 获取仅下载该目录中的 manifest，再次获取仍下载，不重新请求元数据。解析仍离线。
- 最新版以本次显式查询为准，状态文字提示重新查询可刷新；游戏、区服、版本变化或重新查询会使目录及旧文件失效。查询失败不得使用旧目录，不自动回退另一服；下载失败可重试当前目录。
- 本轮仅调整桌面流程、按钮及说明、专项测试和 README。CLI 的动态跨服务查询方式未改，未修改连接策略、下载并发、TLS 校验或新增依赖。

## 国际服分段实测

通过内存 EventListener 调用正式核心方法，记录 DNS、TCP、TLS、HTTP 响应事件及单包下载时间，不打印完整 URL／参数。不清空系统 DNS 或 TLS 缓存；只保证使用新 HttpClient 连接池。

- 本轮没有复现用户约 5 秒的总耗时。
- 首次分支与构建目录合计 1328 ms；两个 API 的 TCP 连接各约 1 ms，TLS 握手分别约 529 ms、407 ms，响应头等待分别约 181 ms、106 ms。API DNS 分别约 8 ms、14 ms。
- 五份下载分别为 245／14／16／14／53 ms，合计 342 ms；共 13,712,650 字节。首次 CDN DNS 约 141 ms，TLS 约 8 ms。
- 第二轮目录 328 ms，五份下载合计 135 ms。
- 本轮证据表明 TCPing 不能代表 HTTPS 总耗时，API 首次 TLS 是该轮主要耗时；不能据此断言用户那轮约 5 秒全由 TLS 造成，也不为此放宽安全验证。

## 待验收及后续

- 启动桌面程序，先选择区服与版本，查询后确认底部具体版本，再获取和解析；切换区服／版本后应必须重新查询。国际服慢不应再拖住官服查询。
- 若用户仍观察到稳定约 5 秒，需对同次操作收集分段计时，不继续盲调连接并发或 TLS。
- 完整交付前仍需独立定位上述桌面布局验证不稳定问题，或取得可靠的基线对照；本轮不将它认定为既有问题。
