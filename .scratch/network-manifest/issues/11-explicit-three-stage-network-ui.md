状态：实现及专项、核心验证完成，待用户验收；桌面完整回归仍有布局失败，未提交。

## 最终确认的流程

用户在选择卡备注中更正早期 categories 预列表方案：不静默联网，也不以当前分支包枚举代替历史版本事实。

1. GUI 顺序为区服／游戏／版本。国服与国际服是已知服务入口，不冒充动态发现全部渠道。
2. “查询游戏列表”：仅对所选服务请求一次 getGameBranches，动态显示原始 biz 及当前版本，不按原神或其他内置游戏名过滤。下方表格为空。
3. 用户选择游戏与版本，点击“查询 manifest 列表”：使用该分支调用 getBuild。只有响应成功后才列出所选版本全部包及其已知元数据，不下载。
4. 用户勾选包，点击“获取 manifest 并解析”：只下载勾选包，执行共用解析、MD5、安全校验及同侧合并，不再查分支／构建。
5. 改游戏／版本立即清空旧 manifest 列表及参考结果；改区服还清空游戏列表，任何选择变化不自动联网。重复操作仅由按钮显式触发。取消及关闭保持可用，失败／取消不发布有效的部分参考结果。

## 实现边界

- `GetGameVersionsAsync` 支持不传游戏筛选；无筛选时保留相同 biz 的多条分支，显示重复 biz 时附原始 game.id；选择记录本身携带对应分支，构建请求不靠 biz 重新猜一条。
- 网络获取解析复用 ReferenceParser，单线程逐包读取、校验、合并，不新增下载调度、重试、依赖或磁盘缓存。网络取消传过链接令牌后，在解析器内部统一为 Parallel.For 所使用的操作令牌，防止取消被误包成一般失败。
- 共用列：文件名／修改时间／大小／状态／游戏／版本／包体／条目数；权重 10／8／4／3／4／4／4／4，新包体列采用建议值 4。删除网络页对游戏／版本的特殊最小宽度覆盖。
- 网络文件名是 category_name，大小为声明的下载大小（Zstd 为 compressed_size），游戏为原始 biz，版本为构建版本，包体为 matching_field，修改时间留空，条目数为解析结果。未选包保留“未获取”，网络不存在等待单独解析的“未解析”状态。
- 离线表格增加同一包体列但留空，不在本轮识别离线资源的游戏／版本／包体信息，原解析流程保留。
- 新游戏动态列出不等于已经验证其 CDN 或清单协议；原官方来源、压缩、加密与格式安全限制未放宽。
- launcher_id 外置并入既有配置待办；完整渠道列表来源见任务 10，方案未定；国际服低速见任务 09，按用户要求暂缓。
