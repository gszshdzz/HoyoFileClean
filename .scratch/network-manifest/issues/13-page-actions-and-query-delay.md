## 网络调查边界

已确认本轮慢由多个 DNS 地址连续连接超时造成，不能只针对首地址或某前缀修补。未证明配置外置导致网络变化，不增加无关请求、并发、重试或自动绕过代理。

Fiddler Tunnel to 表示 HTTPS 代理隧道相关阶段，但仅凭会话名称无法区分隧道建立等待、TLS 或尚未出现解密请求；还需用户确认严重慢是否在 Fiddler 开启前就发生，必要时仅提供该会话脱敏后的 CONNECT 状态码与时间，不要求完整敏感抓包。

## 后续确认与根因修复

- 用户确认不开 Fiddler 已经很慢，因此代理不是该症状的必要条件；未改变或绕过用户代理设置。
- 对 DNS 返回的 20 个地址逐个测量（最多两个并发、每个 2 秒）：前 16 个 IPv4 只有 5 个连通，后 4 个 IPv6 全部约 24–25 ms 连通。仅按不同 IPv4 前缀选第二路不能解决跨地址族排队的问题，不能按特定 IP 或前缀黑名单修补。
- 同官方 HTTPS URL、新客户端连接池、保持最多两个并发及原超时的内存对照两轮：原顺序 4221／4115 ms；第二候选优先另一地址族 155／167 ms，均 HTTP 200、retcode 0。证实主要等待在候选连接排队，不是查询处理或表格，也没有证据指向配置复制导致额外请求。
- 最小产品修复只改第二地址的优先级：先选不同 AddressFamily，无此候选时才按不同前缀；保留 DNS 首地址、剩余尝试、并发上限 2、每地址 2 秒、取消及资源释放。不固定 IPv4／IPv6 优先，不禁用协议，不按游戏或地区分类。
