# HoyoFileClean

对照游戏版本清单检查本地文件。已实现三个命令行模块和四步桌面向导；本次桌面界面的删除只演示确认交互，不删除或移动文件。实际清理尚未实现，原定通过移动而非删除进行。

- 模块 0：把本地 Sophon 构建 manifest 转成 JSON 文件列表，已验收。
- 模块 1：默认轻扫只读路径与大小，可选重扫计算整文件 MD5；支持自定义排除目录和文件。本次按用户授权自动验证和提交前 code-review，不要求人工运行验收。
- 模块 2：对称比较 A、B 两侧的一份或多份 JSON 清单，输出 A 独有、B 独有和共有但不同的文件。

移动与真实删除尚未实现。网络清单获取已接入 CLI 的 `convert --network` 和桌面参考清单页。模块 0 默认的本地转换不联网、不访问游戏目录；模块 1 只读取用户指定目录，不自动获取清单，不修改源文件；模块 2 只读取输入 JSON，不访问 JSON 中记录的扫描根目录，不修改输入。

## 运行

需要 Windows 和 .NET 10 SDK。在项目根目录执行：

```powershell
dotnet build HoyoFileClean.csproj
```

首次构建会获取项目声明的 NuGet 依赖；依赖已缓存时可加 `--no-restore` 离线构建。模块 1 直接使用 .NET 的文件遍历和流式 MD5 接口，没有新增依赖。

### 桌面向导

```powershell
dotnet run --project desktop\HoyoFileClean.Desktop.csproj
```

桌面程序使用 Windows Forms 原生标准控件，无皮肤、自绘或额外 UI 依赖。顶部显示总体流程，每次只显示一步，底部可返回上一步。

进度条由各步骤页面管理，外框不预留共用进度行：参考清单页显示解析进度，游戏读取页显示文件数／字节数双进度，比较页显示比较进度。游戏读取不另设结果文本框，未载入、输入失效、处理完成和失败信息统一显示在底部状态区；详细扫描范围仍可在下一步的两侧摘要核对。

本地获取的候选数量、目录变化提示统一显示在底部，不在表格上方保留空的获取结果行。跨步骤导航按当前有效结果更新提示；修改参考勾选后提示重新解析，不沿用完成提示。失败重扫清零双进度，不保留上次成功的满格。

参考清单默认“自动获取”，其上方用只读文字显示识别出的游戏、版本及需求包体；点击“获取 manifest 并解析”后查询配置中的官方服务，唯一匹配完整 biz，再按识别版本取得全部 manifest，只下载并解析 package 原值匹配的需求包。全部候选仍显示，复选框灰色锁定；缺少身份、三段版本或包体、匹配不唯一、需求包缺失时停止，可切换“网络选择”。后者沿用区服／游戏／版本选择及三个显式网络步骤，包列表默认不选。启动与切换均不自动联网，下载解析和取消复用现有流程，不新增缓存或并发。

游戏读取完成时，底部简要提示实际模式、排除项数量及跳过链接／重解析点数量（不逐项铺开路径），明确这些范围未扫描；历史 JSON 的提示来自记录，不表示重新扫描。排除规则 JSON 在后台读取与校验，期间锁定输入，整份成功后才合并到两侧列表。“导入规则”后方的“导出规则”保存当前排除目录／文件（含当前列表中的预置项），复用核心安全 JSON 写出，拒绝覆盖已有文件；导出的规则可重新导入，路径统一格式后按不区分大小写合并去重，重复导入不增加重复项。排除列表接受多项同类拖入，目录批次中混入文件或文件批次中混入目录时整批拒绝，根目录范围校验失败同样不部分添加。

正式扫描前必须点击“读取游戏并加载预置排除”：只检查配置指定的游戏元信息线索，不计算 MD5、不建立全目录清单；成功读取后显示识别信息、加载可用游戏预置并启用扫描按钮，仍需正式扫描才能下一步。未读取、换根目录、读取失败或取消读取时扫描置灰；读取成功后修改扫描选项／排除规则不需要重复读取。导入历史 JSON 不要求读取当前目录。`ldiff/` 排除扫描，`pkg_version` 和 `Audio_Chinese_pkg_version` 都正常扫描与比较；本轮只提供扫描排除目录／文件，不实现比较排除。预置在 `config/GameFileRules.cs` 集中维护，扫描排除与结果隐藏分别定义，未知游戏不套用；重新加载或切换根目录清掉自动添加的旧规则，保留手动规则。

排除规则导出沿用核心 JSON 写出的失败保留约定：拒绝覆盖或最终文件发布失败时，保存目录可能留下随机命名的 `.partial` 文件；已有目标文件保持不变，不会将临时文件当作成功输出。

其余候选文件仍按原方案排除扫描：原神文件栏应为 `config.ini`、`beyond_pkg_version`，不是空列表。正式扫描携带先前读取的元信息，不重复打开已排除的 `config.ini`；读取后元信息变化需再次点击读取。

1. **游戏读取**：顶部单选“扫描游戏／导入 JSON”，两种来源都须明确指定游戏目录。先成功读取游戏并加载预置排除，再正式扫描；扫描携带预读取的识别结果，MD5 重扫只额外校验文件内容，不是识别前提。结果暂显示在扫描按钮下方。识别与扫描支持“取消扫描”，取消不保留本次结果。排除目录与文件左右分列，单行输入或浏览后添加，在列表中多选移除。规则 JSON 使用 `excludedDirectories`、`excludedFiles` 数组，也可读取历史扫描 JSON 的 `scan` 中的同名字段；导入合并去重，失败不改变列表。路径输入框支持拖入单个相应类型的文件或目录。双进度条仅在扫描过程中显示，结束后隐藏，MD5 数字计数显示在底部。导入历史扫描不重新识别或扫描，仍校验记录根目录与指定目录一致，也不证明当前文件状态未变化。
2. **参考清单**：提供“自动获取／网络选择／本地获取／手动输入”，默认自动获取，启动和切换不自动联网。自动与网络选择共用网络表格，切入或离开自动方式会清空网络行，避免沿用不同游戏或手动勾选；其他切换保留行与勾选，但清空解析状态并使参考、比较及选择失效。手动“添加清单”接受压缩 manifest、未压缩 manifest 和本项目清单 JSON，按内容识别并经过共用安全校验，结果只保留在内存。可手动选择的表格支持表头全选／清空，自动方式的复选框灰色锁定；行高与表头高度不可拖动，列宽仍可调整。
3. **确认与比较**：从左到右分为排除／跳过范围、游戏实际、manifest、输出摘要四栏，使用普通文字而非大文本框。最左栏按排除目录、排除文件、跳过重解析点分组，一项一行，长路径自动换行，项目较多时可滚动查看。两侧输入按字段／值同行对齐，显示已有识别结果、版本、游戏根目录／所选包体、并集文件数、大小和 MD5 已有数／总数；单行摘要长内容省略并可悬停查看全文。网络元数据复用官方列表，离线数据复用共用识别结果，未知显示“—”，不猜测游戏名或包体。页内“比较”使用前两步已载入结果，不提供报告导入；输出游戏独有、参考独有、共有但不同及相同数，轻扫仍计入大小差异，完整校验显示 MD5 相同数，未完整校验显示仅大小相同数，混合参考数据在同一行分别标明两种计数。未比较显示“—”，不冒充零；比较成功才可下一步，不自动跳页。结果仅保留在内存，底部只保留跨页导航和关闭。
4. **结果与选择**：顶部并排多选筛选按钮内显示各类数量（两侧独有、不同、未扫描范围、相同），没有“全部”；带 `✓` 表示启用，默认启用除相同以外的四类，可全部关闭。左右共用行和滚动位置，点击任意一侧目录同步折叠；缺失一侧留白，中间 `←`／`→` 指向独有侧，`≠` 表示不同，`=` 表示相同，`—` 表示未扫描范围。不同文件文字红色、独有文件紫色；相同项悬停状态符号可区分 MD5 相同与仅大小相同。只有已扫描范围内的游戏侧文件可勾选，勾选立即同步底部数量与总大小；关闭分类只取消该分类被隐藏文件的选择，仍显示的已选项保留。已识别游戏默认应用 `config/GameFileRules.cs` 的 `ResultHiddenFiles`，语法与扫描文件预置一致：根目录相对路径、精确匹配、不区分大小写；未知游戏不套用。用户只可勾选“显示隐藏项”，不能编辑规则；重新隐藏会取消隐藏项的选择。隐藏只影响本页，不移除扫描记录或比较结果。本页没有删除、移动或确认操作，下一步操作尚未实现。

结果列表使用虚拟行，折叠复用目录结构，不逐个重建文件单元格；点击文字不留下单元格选中高亮或焦点框。当前四款游戏的隐藏预置仅为 `pkg_version`，不重复扫描排除项；稳定的 `Audio_Chinese_pkg_version` 正常扫描、比较和显示，不属于隐藏项。

目录行及左上角表头提供范围勾选：只选择当前筛选与隐藏开关允许的可选游戏侧文件，目录包括已折叠的子文件。空、部分选中、全选分别显示三态；部分选中点击补全范围，全选后点击清空。参考独有和未扫描项不被范围勾选带入；没有可选文件时表头禁用。范围变化即时同步目录、表头和底部摘要，本页不执行文件操作。

“未扫描范围”是有一侧文件记录、另一侧无记录且该路径落在无记录一侧声明的扫描排除文件／目录或跳过目录链接中的情况；不能据此认定独有或缺失，因此不可勾选。轻扫未计算 MD5 不属于这一类。

识别结果首行有 `biz` 显示 `biz`，否则显示游戏族 `game`，以及已知版本；插件和“发现的包体”另行显示，包体含本体 `game`、语音等规则确定的集合，不代表完整安装，未知不猜测。`channel`／`sub_channel` 仅记录原值，不映射“官服”或限制身份识别。扫描快照及核心 JSON 输出保存可选 `scan.gameDetections`；导入只用记录恢复显示，不访问源游戏文件，旧 JSON 仍兼容。游戏读取页只支持导出排除规则，不新增扫描结果导出。

两类识别区分游戏族 `game`、完整官方标识 `biz`、资源包 `package` 和插件 `plugins`，不互相猜测。自动获取按游戏识别结果匹配官方网络元数据，不关联两份识别配置的检测 ID。扫描、离线解析与网络操作共用页内操作栏，取消位于同行最右侧，底部只保留跨页操作。合并审查与统一验收见 [docs/identification-merge-review.md](docs/identification-merge-review.md)。

上游输入、路径或选项变化会使依赖结果及文件选择失效；参考输入变化不会丢弃独立的游戏扫描。操作期间锁定输入、重复启动和推进，但窗口继续响应。清单解析支持“取消解析”，游戏识别和扫描支持“取消扫描”；取消后丢弃本次结果，等待工作线程退出后可重试或关闭。轻扫和比较不伪造百分比；解析按已处理文件数／总文件数显示确定进度，失败文件也计入已处理，取消不补满。全部文件处理完仍需合并校验，界面会明确显示此阶段。MD5 重扫复用已有进度回调。界面仅显示简短状态，不输出异常调用栈；失败结果不能进入下一步。

桌面的解析、扫描和比较直接传递经过校验的内存快照，不生成中间 JSON，也不创建或读取 `.temp`，重复操作不累积临时文件；关闭窗口后结果释放，后续改写输入文件不改变已载入快照。旧版遗留的 `.temp` 不自动删除，本次也未清理。需要持久化结果时，可在参考清单详情导出该条 JSON，或使用 CLI 转换、扫描、比较；拒绝覆盖、CLI 扫描输出必须在扫描根目录之外等规则不变。GUI 内存结果的来源记录为原始清单路径／实际扫描根目录，不再使用随机临时路径；GUI 已移除报告导入，核心报告导入及身份／内容复核能力保留。

#### 集中维护入口

- `core/Models/`：官方 JSON 协议、网络结果及清单／报告／排除规则的数据定义；protobuf 仍在 `Protos/Sophon.proto`。
- `config/Maintenance.cs`：编译前集中维护默认目录、大小限制、超时、连接节拍、线程数、刷新与缓冲参数，不是用户设置。
- `config/NetworkServices.cs` 与 `config/GameIdentificationRules.cs`：独立的编译期 C# 数据定义，维护者编辑后重新编译，不读取或发布旁置适配 JSON。扩展和验收见 [docs/game-identification.md](docs/game-identification.md)。
- `config/AutomaticManifestRules.cs`：自动获取禁用名单，与游戏识别及 `config/GameFileRules.cs` 的文件规则预置分离；当前绝区零、崩坏三禁用自动获取，其他来源不受影响。
- 两份 `*IdentificationRules.cs` 使用 `Create()` 返回 `IdentificationConfiguration<TDetection>`，每条 `Detections` 自带 `Meanings`；共用 `IdentificationEvaluator` 去重、归并证据和约束结果。两份配置独立，不按检测 ID 匹配；自动获取使用游戏侧输出的 biz、版本和 package 匹配官方响应。manifest 有 `biz` 显示 `biz`，否则显示 `game`。详见 [docs/manifest-identification.md](docs/manifest-identification.md)。
- `presentation/Languages/zh-CN.json`：CLI／GUI 共用文案，直接按字符串 ID 调用，不维护手工 ID 枚举；默认语言在 `config/PresentationOptions.cs`。按当前界面语言加载已嵌入资源，缺少翻译时回退默认语言。只有中文翻译已提供，无语言切换控件；原始标识和路径不翻译，状态逻辑不比较文案。

完整改动列表和统一验收步骤见 [docs/configuration-maintenance.md](docs/configuration-maintenance.md)。

#### 内部分层

- `core/`：转换、扫描、清单读取校验、比较与安全 JSON 写出，不依赖控制台或 Windows Forms；返回数据和结构化错误，不定义用户提示。
- `cli/Program.cs`：CLI 参数、操作调用和退出码；`cli/CliOutput.cs`：面向用户的帮助、摘要、警告、错误；`cli/ProgressDisplay.cs`：终端进度格式。
- `desktop/`：原生向导、界面状态和目录展示，直接引用核心库，不启动 CLI、不解析控制台文字。
- `presentation/`：语言资源与共用错误解释、来源网址脱敏；引用核心错误类型，不向核心反向注入文案。CLI／GUI 保留不同展示方式。

CLI 与 GUI 共用同一套业务逻辑和清单校验。多输入只在核心比较模块内汇总，不新增组合清单模块、组合文件或另一套清单格式。

#### 本地清单获取

切换到“本地获取”，目录输入框默认为 `%APPDATA%\miHoYo\HYP\1_1\modules\sophon\manifest`，可输入其他启动器目录。后方“浏览…”使用系统目录选择器，每次以该默认目录作为初始位置；若目录不存在，系统可能退回可用位置，程序不会创建目录。

点击“获取”只读取当前目录的文件元数据，不解析正文，不递归子目录，不读取链接文件；不按扩展名过滤，因此目录中的普通文件都作为候选清单显示。表格首列为无标题复选框，不显示选中行高亮；接着是文件名、修改时间（到小时）、大小、状态、游戏、版本、包体、条目数、包类型，不显示完整路径。大小单元格自动选择 KB／MB（更大时继续升单位），按 1024 折算、最多三位有效数字并去尾随零，如 `123KB`、`1.82MB`；底层按字节排序。手动页添加、移除、解析在同一行。默认按真实修改时间降序，仅显示时转换为本地时间。未解析时未知游戏／版本／包体、条目数和包类型为空；尝试后无元数据结果显示“—”，失败的条目数同样显示“—”，包类型仅解析成功后填写；其余信息列只读。

用户已确认当前样本中崩坏三和原神清单可解析，崩铁清单尚不可解析；崩铁协议适配留待后续，不据此推断所有游戏／版本均受支持。

本地表格默认按修改时间降序，手动表格默认按名称升序；添加文件保留当前排序。仅本地表格按修改时间排序时，按显示的本地日期与小时交替淡色背景（不增加标题行，高对比度模式禁用淡色）；切换其他列排序即取消。批量添加使用一次 AddRange 发布，表格启用双缓冲，表头复选框仅在位置实际变化时调整。

手动输入可从资源管理器把一份或多份文件拖到表格，效果与“添加清单”一致：按完整路径去重、新文件默认勾选，只读取元数据，不自动解析或移动源文件。目录不递归导入；一批中含目录、缺失文件或元数据不可读项时整批不添加。忙碌时不能拖入，本地获取表格不接受拖放。

本地获取的目录输入框支持拖入单个现有目录，快速填充路径；与手动修改路径一样清空旧结果，但不自动获取或解析。文件、多目录、文本和忙碌期间的拖入不接受，不移动源目录。

分组底色从当前单元格背景色与文字色按 9:1 混合计算，浅色背景略变深、深色背景略变亮，不固定 RGB，也不在本阶段增加深色模式开关。提示区与表格使用同一布局表的自动高度／剩余空间两行，文字换行由布局容器测量，不另用宽度变化回调更新高度。

清单解析默认在后台单线程处理，界面不再显示线程数选项或提示；用户确认流式优化后单线程已足够快。底层仍保留可调并行上限（1–128）及对应测试，未来调用可直接传参，无需逐线程增加代码；GUI 不提供隐藏配置，不修改扫描并行策略。每次开始先丢弃旧参考、比较及差异视图，再解析当前勾选项。每份解析完立即增量合并；一旦出现输入失败或同侧冲突即放弃累计合并结果，整批成功才可推进。为支持逐条详情和导出，成功条目保留独立快照，即使整批失败仍可查看成功行；重试、切换来源或移除行会释放相应引用，不保存原始 manifest 或磁盘缓存。内存由 .NET 垃圾回收管理，不强制 GC 或压缩进程工作集，任务管理器占用不保证立即回到启动值。取消会停止分派后续文件，并在读取／解压、条目校验、合并及发布前检查；同步读调用需等待返回，不保证点击即刻停止，不强杀线程。

三种来源均支持双击已解析行的非勾选列打开详情：上方为游戏、版本、包体、包类型、文件数、覆盖大小及 MD5 记录数／总数的普通文字摘要，自动换行且不可选择复制；中间只读表格显示文件路径、大小与 MD5，底部可关闭或选择位置导出该条目的 JSON。详情与导出使用已载入快照，不重读输入或重新联网，已有输出拒绝覆盖。独立快照使内存占用高于此前只保留合并快照的实现，下述历史峰值不能代表此版本，尚未重测真实大批清单。

状态文字的白块遮挡未被准确复现，也没有确定其重绘根因。已修复的是可复现的固定行高不足导致裁切，并明确设定不透明背景；严重卡顿消失后症状无法复现，不能据此宣称白块根因已解决。如再次出现，应捕获当时画面和负载进一步诊断。

忙碌切换仅锁定按钮、可编辑输入和清单勾选，不再整体禁用／启用页面容器；清单表格保持显示和滚动，信息列始终只读。差异视图仅在比较结果或筛选变化时重建，忙碌更新不重建隐藏树。获取回归捕获的容器状态变化由 48 次降为 0，移除了与用户所述闪白范围吻合的整页重绘诱因；尚未逐帧捕获真实闪白画面，不将此证据表述为独立视觉验收。

manifest 转换采用受限流式读取，不复制或保留完整解压数组；protobuf 使用同字段编号的文件级投影，跳过不用于文件清单的分块详情，不构造分块对象。仍保留压缩／解码大小上限、路径与元数据校验；早期格式错误后也以固定小缓冲读完受限流以保持原大小超限错误的优先级。完整协议定义仍用于兼容样本和测试，CLI 显式输出字段与安全规则不变。GUI 工作线程只更新最新进度计数，界面每 100ms 采样，不按每份文件排队界面消息；表格状态批量索引回填，避免逐行重复遍历。状态文字行按内容自动调整高度，不再固定 44 像素。

1,746 份、共 1,056,634,317 字节的用户默认目录样本曾复现严重停顿：4 线程约 22.9 秒、主线程最长停顿 1,714ms、托管内存峰值约 1.23GB。改为流式／增量处理和定时进度后，同一窗口连续两轮，4 线程约 2.9–4.2 秒、托管峰值约 62–67MB，16 线程约 1.8 秒、峰值约 127–135MB；最长主线程停顿均低于 52ms，未强制回收。此样本整批仍因部分无效输入或同侧冲突被拒绝，不证明解析成功批次的最终清单占用同样大小；离屏测量也不代替真实桌面绘制验收。真实样本诊断为显式测试，不随常规测试自动访问用户目录。

目录变化会立即清空旧表格，空目录正常显示零份，读取失败不保留部分结果。获取不会自动解析；勾选后点击“解析”，各行显示成功／失败及条目数，整批都有效且无同侧冲突才可下一步。勾选集合变化后须重新解析／校验，未勾选文件不会打开。手动页使用同一表格，已导入 JSON 只做共用读取校验，不当作 manifest 再转换。CLI 不增加获取命令，核心的 `ManifestDiscovery.Find(directory)` 只返回元数据，可供后续入口复用。

核心主动校验失败抛出 `CoreException`，通过 `Code`、`Path`、`Input` 提供错误种类与关联路径，原始原因保留在 `InnerException`；不再以中文异常文字作为调用约定。底层文件系统异常仍保留原类型。调用者必须将这些诊断信息转换为自己的展示内容，不能直接向用户显示 `Message`／`ToString()`。CLI 已集中转换这些错误，显示中文说明、错误代码及可用路径，不直接打印 core 或系统异常原文、调用栈。命令、退出码和 JSON 数据字段保持不变；JSON 是持久化数据契约，不是交互文字。

#### 桌面验收

- 解析多份 manifest，或导入有效参考 JSON；无有效结果时不能前进。确认来源、文件数、大小与 MD5 状态。
- 对小型测试目录轻扫，再执行 MD5 重扫；检查排除项、跳过链接警告，以及轻扫不显示“内容校验通过”。重复解析、扫描、比较，确认程序目录不新增 `.temp` 文件；表格行高和表头高度不能拖动。
- 第三步核对四栏摘要：两侧文件数和大小按并集，MD5 显示已有数／总数，包体单行分号分隔，最左栏显示排除和跳过范围；底部无比较／报告导入。轻扫与重扫后分别核对仅大小相同数与 MD5 相同数，轻扫的大小差异仍计入共有但不同数。最小窗口最后一行应可见，长路径悬停可查看全文。本次三分支整合差异与专项验收见 [docs/worktree-integration-review.md](docs/worktree-integration-review.md)。
- 进入第四步，核对多选筛选默认不开相同、无全部分类；显示隐藏项只影响结果展示。点击文字不选中单元格，左右目录折叠后仍同行。
- 勾选文件、目录及左上角表头，检查未选／部分选中／全选和底部数量大小即时一致；折叠子文件仍属于目录范围，参考独有、未扫描和当前隐藏项不能被选入。页面不应出现大文本框、选择确认、删除或移动操作。
- 返回修改输入／扫描选项，确认相关比较与选择状态失效。

自动化测试覆盖离屏原生窗口的四步最小尺寸布局、按钮导航、选项失效及结果列表勾选、隐藏与同步折叠。尚未完成用户实际桌面上的文件对话框及真实游戏目录的人工验收，不将这些项目算作验证通过。

游戏读取合并审查增加失败重扫、规则导入失败保留原结果、历史导入跨页返回、导入失败失效及进度条页面归属检查。桌面测试 85 项，错误、失败、跳过均为 0，另有 1 项显式诊断未运行。最小窗口断言不证明所有 DPI、字体与提示换行组合都不会遮挡；高度不足的滚动兜底方案仅记录，尚未实现，见 `.scratch/desktop-ui/issues/16-game-reading-merge-review.md`。
### 网络获取 manifest

桌面网络列表中的游戏、版本、包体及下载地址均由所选官方服务响应驱动，不内置游戏或包名筛选，不维护逐游戏 CDN 名单。原神及星铁样本已真实验证长度、MD5 和解析；国服四款游戏的构建目录已验证可列出，但不宣称所有游戏、所有包的格式均已验证，压缩、加密和格式通用校验仍保留。可以使用当前版本或手填三段版本号，不枚举历史版本；版本不符不得回退。服务的 `Id`、`NameTextId`、`BranchUrl`、`BuildUrl`、`LauncherId` 位于 `config/NetworkServices.cs`，随核心库编译，不读取旁置 JSON；显示名称引用语言 ID，`launcher_id` 从独立配置项统一编码拼接，两个接口 URL 不预带查询串。开发配置无效会报错，无其他入口回退。不再有默认 biz 或服务器枚举，新增入口只改服务配置和名称资源，不需改业务逻辑；配置供维护者管理，不是用户设置。当前配置两服是已知入口，不冒充自动发现全部渠道；完整渠道来源方案仍待定，预下载不在本轮范围。

**桌面：**来源切换下方按“区服／游戏／版本”排列，列表保持六行可见、更多时滚动。先选择配置中的服务，点击“查询游戏列表”：仅请求所选服务一次 `getGameBranches`，不请求其他服务，不请求构建或下载。显示响应中的完整原始 `biz`，同一 biz 的多条分支保留并附原始 `game.id` 区分，不拆分标识或猜游戏、渠道名称；版本选项显示所选分支当前版本。每次查询游戏列表后游戏均未选中，下方表格为空；用户明确选中游戏后才能查询 manifest，双击实际游戏项目等同明确选中并查询。

选择游戏及当前／自定义版本后，点击“查询 manifest 列表”：复用已查询分支，只请求该游戏与版本一次 `getBuild`，成功后显示全部包，全部默认不选；必须显式勾选才可获取并解析，不依据 game、语言或其他包名推测用户选择。不使用当前分支 categories 冒充历史版本包列表。选择变化不自动联网：切换游戏／版本会清空旧表格与参考结果，需显式重查 manifest 列表；切换区服会同时清空游戏列表。重新查询或请求失败不沿用旧列表。

勾选所需包后点击“获取 manifest 并解析”：只下载勾选包，不重新请求分支或构建；逐包验证下载长度、解压长度、MD5、路径并执行同侧合并校验。复用共用单线程解析器，不新增下载并发、自动重试或磁盘缓存；清单原始正文处理后不留存。表内仍保留所选游戏的全部包，未选包状态为“未获取”，成功包为“已解析”并显示条目数。全部所选包成功且合并有效才启用下一步；失败或取消不发布可用的部分参考结果，允许重试。改选或切换来源使参考结果失效，再次点击会重新下载并解析所选包，网络方式不再有单独“未解析”阶段。

三种来源共用列顺序：文件名／修改时间／大小／状态／游戏／版本／包体／条目数／包类型，默认列宽比例为 8／7／3／3／3／2／4／3／3（勾选列固定宽度）。网络文件名为原始 `category_name`，游戏为 `biz`，包体为 `matching_field`，大小为实际下载声明大小（Zstd 时为 `compressed_size`），修改时间显示“—”，条目数解析后填写。离线来源解析后按开发者规则识别元数据，未命中显示“—”，同一字段命中不同结果值时显示冲突并可悬停查看全部候选；多个 ID 得出同一值不算冲突，规则不猜测缺失信息。

包类型和详情摘要显示“发行版”或“预下载”：本地解析成功后根据已有清单格式标记填写，补丁清单为预下载，其余当前支持的清单为发行版；不重新探测。网络在列表返回时使用官方构建响应的 `branch`，缺少该字段时使用官方游戏分支响应的值，解析不覆盖；未知值显示“—”。映射位于 `config/PresentationOptions.cs`，文案位于语言资源。此显示不新增预下载分支查询功能。详情表格启用与清单列表相同的双缓冲，但实际拖动顺滑度尚未确认。

三个网络步骤期间，页内动作同行最右侧的“取消网络操作”可中断当前请求、正文读取及合并解析，丢弃本批参考结果；底部导航栏不插入网络取消。关闭按钮及窗口关闭仍可用，会先取消操作、收尾后自动关闭。不改变扫描或离线解析原有的退出行为。左键双击区服实际项目等同“查询游戏列表”，双击游戏实际项目等同“查询 manifest 列表”；双击空白处不操作，忙碌时不重复请求，普通改选仍不自动联网。

**CLI：**`--network` 是 `convert` 的可选参数；选用后 `--service`、`--biz`、`--version`、`--package` 全部必填，本地 manifest 参数不再提供，只提供输出 JSON 路径。`service` 使用配置中的 `Id`（不是内置服务器枚举），`biz` 使用完整官方 `game.biz`，资源包使用构建目录的原始 `matching_field`，不猜测或拆分。仅查询指定服务；同一 biz 有多个分支时，须用 `--game-id` 指定原始 `game.id`，否则明确报错，不选择第一项。版本可写 `latest` 或三段具体版本号。旧 `--game`／`--region` 拆分参数和隐式默认本体已移除。

以下只是已验证的示例，不是允许值名单；接受新增标识不等于已验证所有格式，通用格式、压缩、加密及请求来源校验仍保留，不增加逐游戏 CDN 限制。

```powershell
dotnet run -- convert "reference.json" --network --service china --biz hk4e_cn --version latest --package game
dotnet run -- convert "reference-old.json" --network --service global --biz hk4e_global --version 7.1.0 --package zh-cn
```

不传 `--package` 时在联网前报参数错误，不默认选择任何包。`--package` 最多指定一次，每条 CLI 命令只转换一个包；重复同值或不同值都在联网／写出前报参数错误，退出码 `2`。语音 `zh-cn`／`en-us`／`ja-jp`／`ko-kr` 只是示例，不是硬编码名单。只下载选中的包，输出一份可供现有比较模块读取的 JSON。未知选项、缺少／重复必选参数、空值及版本格式错误也返回退出码 `2`；配置中没有所选服务、官方返回中没有指定 biz／id／资源包，以及请求、校验或写出失败返回 `1`，不发布部分结果；已有输出在联网前拒绝，仍不覆盖。GUI 多项勾选与核心多清单合并能力保持不变。

**核心调用：**`GetGamesAsync(service)` 读取完整原始 biz/id；`GetGameVersionsAsync(service)` 保留响应中的独立分支，GUI 直接传所选分支给 `GetCatalogAsync`，不会重新查询分支。CLI 使用 `GetCatalogAsync(service, biz, ..., gameId: ...)` 精确匹配。`GetCatalogAsync` 的 `version` 默认 `null`，表示当前版本；指定时按原值请求。`FetchAsync` 下载并检查长度，`Read` 在内存中解析与校验；`ReadAsync` 完成两步。`ConvertAsync` 要求显式指定一个包，复用既有安全 JSON 写出。

```csharp
using HttpClient http = NetworkManifestClient.CreateHttpClient();
var network = new NetworkManifestClient(http);
NetworkService service = NetworkManifestClient.Services.Single(item => item.Id == selectedServiceId);
RemoteManifestCatalog catalog = await network.GetCatalogAsync(service, selectedBiz, cancellationToken, gameId: selectedGameId);
RemoteManifest selected = catalog.Manifests.Single(item => item.MatchingField == selectedPackage);
FileListSnapshot snapshot = await network.ReadAsync(selected, cancellationToken);
```

正式联网使用 `CreateHttpClient()` 创建并复用客户端，禁用自动重定向；构造器允许传入客户端供测试使用，自定义客户端同样必须禁用重定向。查询入口从项目配置读取，只依赖官方接口；下载采用官方构建响应返回的具体 URL，不依赖第三方维护的清单服务，也不维护 CDN 白名单。联网下载对象须由官方构建响应产生，手工构造或替换其 URL 后不可下载；离线 Read 不需要此来源标记。通用地址限制为 HTTPS、默认端口、无用户信息或片段，拒绝重定向，继续执行长度、摘要及格式校验。此方式信任官方 API 给出的地址，不对 API 本身错误或被攻击后的响应提供独立域名白名单防护。无需账号，不下载游戏正文或补丁。

首次慢曾复现为多个 DNS 地址 TCP 无法连通。客户端将 DNS 地址按 IPv4／IPv6 分组，各族内保留原顺序、去重；初始每族尝试一个，此后每 0.5 秒每族新增一个候选，每个连接最多等待 1.5 秒。某族没有候选就不启动，不探测网络环境、不合成地址；纯 IPv4／IPv6 都使用同一流程。无额外并发数量上限，数量由节拍及单连接超时自然约束，超时边界可短暂重叠。先成功者胜出并取消、释放其他连接；TLS、代理和连接复用仍交给 .NET。不固定 IP、不按前缀选路、不禁用地址族、不预联网、不并发下载，网络耗时不承诺固定上限。

下载检查实际长度，即使响应没有 `Content-Length` 也执行上限；压缩输入最多 64 MiB，未压缩及解压内容最多 128 MiB，元数据最多 2 MiB。核对元数据声明的压缩方式、下载长度、解压长度和解压后 MD5，复用本地 manifest 的流式解析及条目校验。拒绝加密、未知压缩方式和 JSON 代替 manifest；不发布失败的部分结果。每次查询或读取有两分钟整体取消期限，调用者可提前取消；同步解析会在读取与条目校验处检查取消，不保证立即停止。

GUI 当前批次的下载字节与解析快照仅保留在内存，不创建磁盘缓存或中间文件、不访问游戏目录；换条件或重新获取后旧下载释放引用，重复解析复用当前批次字节。CLI 按指定路径写出最终 JSON。快照来源保留实际清单 URL，冲突仍按共用规则拒绝。获取成功不证明本次清单覆盖安装目录的全部资源。

### 本地 manifest 转换

转换本地 manifest，无需手动判断或处理压缩情况：

```powershell
dotnet run --no-build -- convert "manifest路径" "输出路径.json"
```

每份输入独立转换，不合并；接受压缩 manifest、未压缩 manifest 或本项目现有清单 JSON，按内容自动识别，不提供格式参数。JSON 复用比较模块的读取与校验，保留哈希与扫描范围；不接受任意 JSON 或旧脚本格式。无效输入不会生成最终 JSON。

### 本地目录扫描

默认是轻扫，只读取路径与大小，没有过程进度，结束时输出摘要和必要警告。下面的路径需替换为自己的路径；每个排除选项可以跟多个路径，也兼容重复选项的旧写法：

```powershell
dotnet run --no-build -- scan "扫描根目录" "扫描目录之外的输出路径.json" `
  --exclude-dir "Cache" "Data/Optional" `
  --exclude-file "settings.ini" "Data/private.bin"
```

需要内容校验时，在命令中加入 `--hash`，并选择新的输出文件名。重扫先复用轻扫得到的列表与总大小，再按列表计算 MD5，不重新枚举目录。

重扫在交互终端按已读取字节显示百分比、文件数和大小，同一行每 0.5 秒最多一次常规刷新，开始和结束另有更新。进度使用 ASCII 文本，连同清尾填充限制在终端列宽减一内，窗口缩小时也不折行刷屏。输出到文件或管道时不显示动态进度；轻扫不触发进度回调。

- 不指定排除项时，扫描根目录中的普通文件，包括隐藏文件、系统文件和零字节文件；空目录可正常输出空列表。
- 排除项按完整路径精确匹配，支持根目录内的相对路径或完整绝对路径，匹配时忽略大小写、统一分隔符。不支持通配符，不能排除根目录本身或根目录外的路径。
- 普通盘符和 UNC 路径的 `\\?\`、`\\.\` 前缀别名会统一归一化，不能借前缀绕过目录边界；其他设备卷路径明确报不支持。
- `--exclude-dir "Cache"` 排除该目录和全部子目录，不影响 `Cache-other`；`--exclude-file "settings.ini"` 只排除根目录的该文件，不影响其他目录的同名文件。
- 排除路径可以尚不存在，不会因此报错。参数会规范化后记录在结果中，程序没有预设排除目录或文件。
- 软链接、目录联接及其他 Windows 重解析点都不进入扫描；明确排除的目录／文件优先应用排除规则，不重复计入跳过链接。其余链接成功时逐项在标准错误中警告，并在 JSON 的 `scan.skippedLinks` 中记录。已排除目录中的内容不再遍历。
- 根目录、输出目录或它们的父级路径含链接或重解析点时，明确报错，不通过链接访问或写出。
- 无法访问目录或文件元数据时停止，不静默遗漏文件。轻扫不打开文件正文，正文被占用但元数据可访问时仍可完成。
- 重扫在读取前重新确认路径、类型与列表记录的大小；正文无法读取、被写入占用、发现类型或大小变化时停止，不发布部分哈希结果。哈希使用只读文件流，读取期间不允许其他进程通过普通文件句柄写入或删除该文件。
- 文件条目按相对路径稳定排序。输出必须位于扫描根目录之外；相对输出路径以当前工作目录为基准，不是扫描根目录。

轻扫读取目录枚举中的文件大小，不读取正文；重扫才读取所有未排除的普通文件内容，耗时随数据量增加。结果反映枚举或读取时的状态，不是整目录的原子快照；路径检查也不构成对恶意并发路径替换的文件系统隔离。

程序内可直接调用 `DirectoryScanner.Scan(rootPath, outputPath, excludedDirectories, excludedFiles)` 轻扫，或额外传入 `computeHashes: true` 重扫。可选 `progress` 回调同步接收已完成文件数、文件总数、已读取字节和总字节；扫描逻辑不依赖控制台。

### 清单比较

两侧都接受模块 0 或模块 1 生成的 JSON，不接受旧 Python 脚本格式或原始 protobuf。A、B 只是身份标签，交换两侧后，独有项和差异详情也相应交换，没有“正确清单”一侧。

```powershell
dotnet run --no-build -- compare "比较结果.json" `
  --a "本地扫描.json" `
  --b "本体清单.json" "语音包清单.json"
```

`--a`、`--b` 均可跟多份清单，也可以重复；所有输入及输出路径均以当前工作目录为基准。只在内存中汇总各侧条目，不生成组合清单。输入路径记录在报告的 `aInputs`、`bInputs` 中，保留各自身份，不推断游戏、版本或清单覆盖完整性。

- 路径统一分隔符后按 Windows 大小写不敏感规则比较，保留各条目的原始大小写，输出稳定排序。
- 同一侧多份输入的重叠路径，大小和 MD5（或均未计算哈希）一致时去重；记录矛盾则报输入错误，停止输出。单份输入中的重复路径及跨输入的文件/父目录冲突也会被拒绝。
- **两侧之间大小或 MD5 不一致是正常结果，不是运行错误。** 共有路径只有在双方都有 MD5 时才比较哈希；否则只比较大小，不能推断内容一致。
- 对侧明确排除的文件、目录及跳过链接的路径范围归入 `outsideScope`，不混入独有项；目录范围包含子项但不包含相似前缀目录。多份输入中的排除范围保守取并集；另一份清单确实提供该路径时仍正常比较。
- `onlyA`、`onlyB` 分别保存两侧独有的文件条目；`different` 保存共有但不同的条目，包含 `a`、`b`、`sizeDifferent`、`hashDifferent`、`hashCompared`。`outsideScope` 保存未比较条目的 `presentIn`（`a` 或 `b`）和 `file`。
- `summary` 统计上述数量，以及 `matchedWithHash`（大小与 MD5 一致）和 `matchedSizeOnly`（仅大小一致、未校验哈希）。一致条目不逐条输出，避免冗余。

独有仅表示本次选用清单中的集合差异，不证明文件无用或安装缺失；比较结果不是移动指令。

### 输出与退出码

三个命令都要求输出的父目录已经存在，已有输出文件会被拒绝，不覆盖。成功返回退出码 `0`，处理失败返回 `1`，命令参数格式错误（缺少参数、未知选项等）返回 `2`。比较发现差异仍返回 `0`；同侧矛盾或清单损坏返回 `1`。跳过链接且其他扫描成功仍返回 `0`，但会有警告和范围记录。

结果先写入同目录的唯一 `.partial` 文件，写入并关闭成功后才改名为目标 JSON。写入、关闭或发布失败可能保留 `.partial`，但不会把它作为成功结果发布；已有目标不被覆盖。

## 输出格式

manifest 转换与重扫保留完整哈希字段：

```json
{
  "hashAlgorithm": "MD5",
  "fileCount": 1,
  "totalSize": 3,
  "files": [
    {
      "path": "Data/example.bin",
      "size": 3,
      "hash": "900150983cd24fb0d6963f7d28e17f72"
    }
  ]
}
```

- `path` 是文件相对路径，分隔符统一为 `/`，保留路径大小写。
- `size` 和 `totalSize` 的单位是字节。
- `hash` 是整文件 MD5，统一为小写，不是分块哈希；转换时读取 manifest 中记录的值，重扫时计算本地文件内容。
- 转换只输出 `asset_type == 0` 的文件条目，不导出分块数据。

轻扫保留 `fileCount`、`totalSize`、`files[].path` 和 `files[].size`，省略 `hashAlgorithm` 和 `files[].hash`，表示未做内容校验；没有空哈希或伪造的 MD5。

两种扫描结果额外包含扫描范围和模式，例如：

```json
{
  "scan": {
    "root": "D:\\Game",
    "excludedDirectories": ["Cache"],
    "excludedFiles": ["settings.ini"],
    "skippedLinks": ["Data/link"],
    "mode": "light"
  }
}
```

`scan.mode` 为 `light` 或 `heavy`；排除项和跳过项都是相对根目录的路径。轻扫可以用于路径与大小差异筛查，不能被当作哈希校验通过。扫描清单只覆盖本次选定的普通文件范围，不能因某文件被排除或跳过便认定它缺失、无用或可移动。

转换时的空文件列表、损坏数据和无效文件大小或 MD5 会被拒绝。两个模块均在发布结果前校验危险相对路径、Windows 保留设备名、重复路径、文件与父目录路径冲突及总大小溢出；路径冲突按 Windows 的大小写不敏感规则判断。

manifest 转换限制压缩输入最多 64 MiB、解压后最多 128 MiB；这是工具的资源保护上限，不是游戏协议的限制。该限制不用于本地扫描文件大小，扫描不会整文件读入内存。
