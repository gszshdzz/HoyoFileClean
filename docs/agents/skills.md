# 技能路由与适配

技能是工作手册，不是自动运行的保护钩子。先检查宿主可用列表，用 `skill` 实际加载当前阶段匹配项，再按返回路径读取附属资料；已有完整上下文可复用，压缩后缺失则重载。不以列名称代替调用、不等用户点名、不整套加载；用户可见加载记录，不另行播报或汇总。

## 必须检查的阶段

| 阶段／触发条件 | 技能 | 使用边界 |
| --- | --- | --- |
| 提方案，有影响操作、安全或验收的产品歧义 | `grilling` | 先查事实，再补具体决策；普通明确小修不访谈。 |
| 修改职责、共享逻辑或重要架构 | `codebase-design` | 保持现有分层，不附带全仓重构。 |
| 新增／修改业务术语或记录难逆取舍 | `domain-modeling` | 只记录已决定内容，使用 `GLOSSARY.md`／`docs/adr/`。 |
| 实现 C# 语言、异步或资源问题 | `csharp-expert` | 专项技能优先，未安装的插件不假装可用。 |
| Windows Forms 页面、布局或交互 | `winforms-expert` | 直接加载，不重复走 C# 路由；不引入 Designer／MVVM。 |
| 新增或修复可测试行为 | `tdd` | 重要行为先见失败，再最小实现，使用现有 xUnit v3。 |
| 故障或性能回归 | `diagnosing-bugs` | 先复现再找根因；定位 .NET 热点后再用 `analyzing-dotnet-performance`。 |
| 新增／明显修改测试或检查弱断言 | `assertion-quality` | 检查独立期望、失败、状态和副作用，不追求断言数量。 |
| 重要状态链、安全分支或担心漏测 | `test-gap-analysis` | 映射可见行为到测试，未实验证明不称已验证缺口。 |
| 文件操作／危险配置设计 | `sharp-edges` | 范围、链接、覆盖、失败、取消保护；纯文案不套安全审计。 |
| 路径、解析、网络来源、真实移动等安全改动审查 | `differential-review` | 相对基线追踪完整调用与校验，以隔离样本确认可达性。 |
| 完整业务交付／提交前 | `code-review` | 规范与需求分开，覆盖新增及未提交文件；小型文档调整自检即可。 |

测试分析另读取 `.opencode/skills/test-analysis-extensions/SKILL.md` 及 `extensions/dotnet.md`；它是参考目录，不作为可调用技能。

## 项目适配

- 用户保留范围、方案、重要取舍和验收决定权；用效果、风险和维护代价说明推荐。日常实现细节在授权内连贯完成，重大兼容、依赖、不可逆结构或明显资源取舍先确认。交付与提交仍遵守根 `AGENTS.md`，技能不扩大权限。
- 保持现有框架、编译期业务配置和共用语言资源；第三方 API 用法仍先查 Context7。不因示例增加依赖、迁移架构或引入第二套流程。
- 上游 Bash、Task、Claude 插件及专用代理名转换为当前宿主能力；缺少关键能力如实说明。默认自行调查；`code-review` 的完整双轴审查可用两个只读代理，架构多方案并行仅在用户要求时使用，不自动启动大型 workflow。后台代理等通知，不轮询。
- 编译、自动测试、离屏布局、真实桌面、Designer 和性能测量分别报告，不能互相冒充；安全怀疑先追踪与复现，未证明则标待确认。
- 测试遵守 `docs/testing.md`；测试临时文件用 `TestTemporaryFiles.Root`，人工日志／截图用获准系统临时目录，不在真实游戏目录破坏性验证，不修改未知用户工作来证明漏测。
- 方案使用本地 Markdown，不为技能强造 spec；可使用本次已确认要求审查。按模块验收，不自动提交或推送。

本地入口已适配 Windows、宿主工具、用户控制权和审查范围；附属参考除另记的失效链接修正外保持上游内容（当前无此类修正）。更新须对照固定版本、许可、引用与工具要求，保留本地适配，不全量覆盖、不自动更新或运行上游脚本。安装证据见 [历史记录](../history/skill-installation.md)。
