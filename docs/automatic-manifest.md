# 自动获取规则

操作步骤见 [使用指南](usage.md#自动获取)。自动获取共用网络页面、下载校验、解析、取消和失败处理，不新增库、磁盘缓存或并发。

## 匹配与失败

- 使用游戏识别结果的完整 `biz`、三段 `version` 和全部多值 `package` 原值，不按两份识别配置的检测 ID 关联。
- 查询配置中的官方服务，确认完整 biz 分支唯一；按识别版本取得全部 manifest，需求包全部存在才下载、解析和合并。先查询身份列表，避免无关游戏的异常版本阻断目标。
- 缺身份、坏版本、身份不唯一、缺需求包或任一服务查询失败均停止，不用其他游戏、版本或部分包替代。失败或取消不发布可用的部分参考结果。
- 显示全部候选，需求包勾选且锁定，未选包保持未获取；不是让用户手选的“网络选择”方式。
- 切入／离开自动方式清空网络行，避免沿用旧游戏或手动勾选。启动和来源切换不自动联网。

## 不完备规则限制

`config/AutomaticManifestRules.cs` 的 `IncompleteGames` 为编译期禁用名单，按已识别的 `game` 或完整 `biz` 原值匹配；仅有 biz 的历史扫描同样受限，不拆分 biz 推测游戏族。

当前绝区零、崩坏三因包体识别不完备禁用自动获取，默认转为网络选择；其余来源不受影响。获得充分识别证据后，才能移除名单并重新构建。名单不改变识别输出，与 `GameIdentificationRules` 和 `GameFileRules` 分开维护。

## 回归检查

检查匹配所用版本与包体、完整候选和勾选锁定、无关游戏坏版本、缺信息／缺包拒绝、取消后重试，以及切回网络选择后默认不选包。网络模拟与真实官方请求分开说明；专项入口见 [测试说明](testing.md)，历史证据见 [交付记录](history/automatic-manifest-delivery.md)。
