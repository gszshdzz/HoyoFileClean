# 不看代码也能指导开发

你保留“做什么、采用什么方案、重要取舍、是否验收通过”的控制权；AI 负责调查、提出建议、在你确认的范围内实现并验证。不懂代码不等于全权委托，也不意味着只能最后看效果。技能由 AI 按阶段主动调用，你不需要记住名字。

## 已安装技能分类

| 类别 | 技能 | 对你有什么用 |
| --- | --- | --- |
| 需求 | `grilling` | 先补齐容易理解错的操作与边界，避免做完才发现不是你要的 |
| 业务术语 | `domain-modeling` | 保持“清单外、缺失、未扫描、受保护”等概念一致，不把清单外文件直接当垃圾 |
| 架构 | `codebase-design` | AI 提出功能划分与共享方案，用通俗后果说明重要取舍，由你确认 |
| 实现 | `csharp-expert`、`winforms-expert` | C# 与原生 Windows 桌面专项指导 |
| 测试 | `tdd` | 重要功能先有能发现错误的测试，再实现 |
| 测试质量 | `test-gap-analysis`、`assertion-quality` | 检查漏测和“假通过”，不只报一个通过数量 |
| 排错与性能 | `diagnosing-bugs`、`analyzing-dotnet-performance` | 先复现、找原因、测量，再修复，不靠反复猜改 |
| 交付审查 | `code-review` | 分别检查代码是否符合规范、结果是否符合你的要求 |
| 安全 | `sharp-edges`、`differential-review` | 重点检查路径、覆盖、异常输入和未来真实移动的风险 |

另有 `test-analysis-extensions` 参考目录，供 AI 查 xUnit 等测试框架的规则，不是需要你调用的功能。

来源为 `mattpocock/skills`、微软官方 `dotnet/skills`、安全公司 `trailofbits/skills`；具体版本与许可见 `.opencode/skill-sources.json` 和 `docs/agents/skills.md`。

## 怎样合作

1. **你描述效果**：哪个页面、现在怎样、希望怎样、哪些行为不能改；不必提供实现方法。
2. **AI 查事实并推荐**：先核对现状，再说明范围、风险和验收方法；重要选择用卡片解释后果，必要时给草图，不能让你在陌生术语中盲选。
3. **你确认重要方案**：新功能、交互和重要架构变化先确认。文件操作范围、失败后保留内容、依赖、兼容和明显资源取舍由你决定；日常类名和测试写法不逐项审批。
4. **AI 连贯完成并验证**：明确授权的小修不重复审批；范围改变或出现新风险则暂停。检查适用的错误输入、取消、重试、结果失效和旧功能；文件操作用隔离样本，不破坏真实游戏文件。
5. **按模块交付验收**：说明改了什么、可运行入口、操作与预期、实际验证和未验证项。编译、离屏测试、真实桌面及性能证据不能混为一谈。
6. **认可后保存成果**：你明确验收，AI 按项目规则检查并提交，自动分配 session 编号，同一 session 多次提交沿用；实际修改用纯数字，合并用箭头，worktree 留待合并 agent 补号。无法确定时再询问，提交后报告编号，供你命名 session；不自动推送或发布。一个模块通过再开始下一个。

涉及账号、权限、工具、设备、签名或发布渠道的新阶段，AI 应一次列全缺项和分工。你随时可暂停、追问、否决或要求更简单的方案；询问或质疑不自动成为修改授权。

可直接这样提出需求：

> 修改【页面／功能】。现在【现象】，希望【效果】。保留【不能改变的行为】。先给推荐方案和验收标准，确认后再实现。

## 技能与验证的限制

技能由 AI 按阶段主动加载，你不需要背清单或替 AI 跑可自动完成的检查。工具加载记录可直接查看，AI 不另行播报；写出技能名称或安装成功不算实际执行。

目前没有保证每次强制调用的程序钩子，技能也不保证零缺陷。验收应同时看实际效果、测试证据和验证限制；具体 agent 规则只维护在 `AGENTS.md` 和 `docs/agents/skills.md`。
