# 两类识别合并审查

编号：`8,9->7.5`。基线：`main c60b8a8`；游戏识别：`f037a9b`；manifest 识别：`2e6b6f2`。

## 总体差异

- 向导先识别并扫描游戏，再获取参考清单；识别或扫描失败、取消后不发布结果，允许重试。
- 游戏结果紧凑显示完整游戏标识、版本、渠道及动态插件；扫描 JSON 可携带识别记录，旧 JSON 兼容，导入不访问原游戏目录。
- manifest 使用 20 条编译期规则识别游戏族、确定的完整标识和资源包；未知不猜、冲突保留证据，不改变文件比较规则。
- 三种参考来源均可双击成功行查看已载入快照、文件列表并导出单条 JSON；不重读源文件、不重新联网、拒绝覆盖。
- 网络入口、游戏规则和 manifest 规则都在 `config/` 维护并编译，不增加依赖或旁置配置。

## Standards

两路静态审查发现 2 项判断性问题，未发现硬违反；均已修正：

1. 原游戏信息键 `game_id`／`packages` 与 manifest 的含义不一致。统一完整标识为 `biz`、插件为 `plugins`；manifest 的 `game` 仍是游戏族，`package` 仍是资源包。原始 `scan.gameDetections` 键不变，不把插件推断成资源包。
2. 扫描取消紧随动作按钮，解析和网络取消在右侧。三者改用同一个 `OperationActions` 布局，取消均在操作行最右侧；底部导航不随忙碌插入按钮。

整合复查另移除解析结果中重复保存的元数据，直接取自成功快照；移除重复清空调用。详情导出错误改用共用桌面诊断，保留已有输出的明确提示，不再借用 CLI 展示入口。

两引擎不强行合并：游戏识别负责受限读取安装配置、必要信息和版本归并；manifest 识别只读已校验清单、提供提示和冲突证据。提取对象与失败语义不同，抽象成同一引擎会增加分支而不减少业务规则。

人工验收时，用游戏副本操作：

1. 扫描支持的原神国服目录，检查首行 ID／版本／渠道及插件另行显示；取消 MD5 重扫，确认不能前进且可重新扫描。
2. 进入参考页，用本地或手动来源解析本体和语音 manifest；检查游戏名称、资源包和未知版本，双击成功行查看文件和来源。未解析／失败行不能打开详情。
3. 在详情中导出新 JSON，再选同一路径导出，应提示已存在且原文件不变；网络来源同样操作，双击和导出不应触发新请求。
4. 对比扫描、本地／手动解析、网络操作：取消都在操作行最右，底部导航顺序不变；改选和切换来源后旧详情不可用，整批失败不能下一步。
5. 完成比较，检查游戏独有、参考独有、不同和未扫描范围；插件信息不能导致自动勾选网络包或改变文件差异。

真实桌面保存对话框、不同 DPI 视觉、大批成功清单的内存峰值需人工／专门测量；常规离屏测试不代替这些验收。本轮不重跑真实联网或读取用户目录的显式诊断，分支此前的真实样本结果不算作本轮验证。
