# 按需测试与自动收尾

两个测试项目分别覆盖核心／CLI 和原生桌面界面。平时只运行与改动有关的测试类，不为了每次编辑反复执行两套全量；不移除重复断言或降低安全回归覆盖。

两项目分别验证核心／CLI 和 Windows Forms 线程、消息循环及界面行为，不因场景相似而删用例。原生宿主复用正式入口的字体、视觉样式与 DPI 初始化；不要维护另一套测试专用设置。历史耗时与保留依据见 [测试评估](history/testing-assessment.md)。

```powershell
# 核心比较：多个类在同一次运行中执行
.\tests\run-tests.ps1 -Suite Core -Class FileComparerTests,ComparisonInterfaceTests
# 桌面改动
.\tests\run-tests.ps1 -Suite Desktop -Class ComparisonPanelTests
# 阶段结束、公共接口或共用测试设施变更时，明确执行一次全量
.\tests\run-tests.ps1 -Suite All -Full
```

入口不默认全量；每次按需运行只构建所选项目，依赖已还原时使用 `--no-restore`。首次依赖还原仍按 README 构建说明执行。同一份代码已构建且未再修改时可加 `-NoBuild`；修改之后不能用旧二进制证明新代码正确。不添加基于时间戳的测试结果缓存，避免漏测。

普通运行排除显式测试。联网、用户真实缓存目录、未跟踪的真实样本仅按需选择相应类并加 `-Explicit`，不能随 `-Full` 启动。类内若有多个显式诊断，需进一步选择单个方法时，直接使用现有 xUnit 入口的 `-method` 参数。

## 临时文件

两套项目共享 `tests/TestTemporaryFiles.cs` 的代码，每套每轮独立创建 `%LOCALAPPDATA%\Temp\opencode\test-runs\<程序集名>-<随机编号>`。测试清单、模拟缓存、扫描目录和自动截图都写在自己拥有的目录内。xUnit assembly fixture 在测试结束后直接永久删除本轮目录，测试断言失败也会收尾；用户已明确授权此限定自动删除，不使用回收站。

清理跳过链接目标，只移除链接本身；支持测试创建的只读文件。清理失败会作为测试框架错误报告，不吞掉异常。进程被强杀、系统崩溃或仍有文件被占用时不保证清理成功，不添加后台清理或扫描历史目录的机制。`test-runs` 空父目录允许保留。

真实游戏／启动器缓存是只读输入，不删除；NuGet 缓存、`bin`／`obj` 是构建复用数据，也不自动清理。历史遗留的临时目录和固定截图不纳入本轮所有权，不自动扫除。

## 验收

先执行 `TestTemporaryFilesTests`，验证嵌套缓存、只读文件、目录链接与共享父目录保护。共用设施变化后执行一次两套常规回归，检查通过数及错误数，并确认 `test-runs` 内本轮目录已消失；不需要重复跑联网或真实样本诊断。

没有匹配测试（`Total: 0`）视为失败，不能当作验证通过。交付时记录本次实际运行、失败及显式未运行项，不在本指南累积历次测试数量；离屏自动化不替代真实系统对话框、所有 DPI 或人工视觉验收。
